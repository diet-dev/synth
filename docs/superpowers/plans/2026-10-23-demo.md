# Демка-генератор звуков — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Страница на GitHub Pages: примеры звуков, генератор по категориям, редактор всех параметров пресета, режим цикла, копирование пресета в код.

**Architecture:** Чистая логика (схема параметров, операции над пресетом, генераторы, сериализация, планировщик цикла, очередь рендера) — отдельные модули в `demo/` без DOM, покрытые `node:test` из `test/`. Поверх них тонкий DOM-слой (`editor.ts`, `wave.ts`, `audio.ts`, `main.ts`). Рендер всегда в Web Worker; звук — Web Audio. Vite собирает `demo/` в `dist-demo/`, workflow выкладывает на Pages.

**Tech Stack:** TypeScript (strict, ES2022, NodeNext), Vite 8 (devDependency), Web Audio, Web Worker, `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-23-demo-design.md`

## Global Constraints

- Пакет без runtime-зависимостей; `vite` — только devDependency. Публичный API `src/` не меняется.
- Демка не попадает в npm: `files` в `package.json` не трогать; `dist-demo/` — в `.gitignore`.
- Демка импортирует пакет как `../src/index.ts` (тесты демки идут в Node, где `@dietdev/synth` разрешился бы в собранный `dist`; алиасов нет).
- Интерфейс и комментарии — на русском. Целевой экран — десктоп от 1280 px, мобильная вёрстка не нужна.
- Тёмная и светлая тема — по `prefers-color-scheme`.
- Никаких упоминаний других проектов автора в коде, именах, коммитах (см. память проекта).
- Тесты: `npm test` (`node --test "test/*.test.ts"`, Node ≥ 22.6), `npm run typecheck` должен покрывать `demo/`.
- Коммиты — от Diet Dev, с трейлером `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Лимиты групп (из спеки, точные значения — решение плана):
  `game: { maxMs: 1500, maxPeak: 0.8 }`, `own: { maxMs: 400, maxPeak: 0.7 }`, `ui: { maxMs: 150, maxPeak: 0.4 }`; частоты тона в генераторах 30…8000 Гц.
- Период цикла по умолчанию `DEFAULT_PERIOD = 216` мс; варианты цикла — сиды `[1, 2, 3]`; пул на вариант — 10; упреждение планировщика — 0,2 с.

## Review Focus

1. **Крайние значения ползунков** (все поля на min или на max, `pulses.rate` = 0, нулевая огибающая, `ms` = минимум) — рендер без NaN и без исключений, тишина допустима. → тест в Task 1.
2. **Битый или старый `#hash` в адресе** (обрезанный, не base64, не тот JSON, пресет без голосов) — страница открывается с примером по умолчанию, без ошибки. → тест в Task 2.
3. **Удаление последнего голоса** — запрещено (операция возвращает пресет без изменений), иначе `peak` и редактор ломаются. → тест в Task 1.
4. **Числа в экспоненциальной записи и отрицательные** (`1.1564625850340137e-7`, `-0.000027`) в коде пресета — код остаётся валидным JS и даёт тот же звук. → тест в Task 2.
5. **Смена звука или периода во время цикла** — новые клипы идут со следующего перезапуска, уже запланированные доигрывают, сетка перезапусков не сбивается. → тест в Task 4.

### Task 4: Планировщик цикла

**Interfaces:**
- Produces:
  ```ts
  export type Start = { at: number; variant: number }; // at — секунды по часам AudioContext
  export class LoopScheduler {
    constructor(rand: () => number, pool?: number); // pool по умолчанию 10
    start(now: number): void;                      // первый перезапуск — в now
    setPeriod(ms: number): void;                   // действует с ближайшего незапланированного
  ```

### Task 5: Очередь рендера и воркер

**Files:**
- Create: `demo/renderer.ts`, `demo/render.worker.ts`, `test/demo-renderer.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export type RenderJob = { preset: Preset; seeds: number[] };
  export type Backend = (job: RenderJob) => Promise<Float32Array[]>;
  export const directBackend: Backend;          // renderVariants в том же потоке
  export function workerBackend(): Backend;     // new Worker(new URL("./render.worker.ts", import.meta.url), { type: "module" }); буферы — transfer
  export class Renderer {
    constructor(backend: Backend);
    /** Одновременно в работе не больше одной задачи; новая заявка вытесняет ждущую. Вытесненная получает null. */
    request(job: RenderJob): Promise<Float32Array[] | null>;
  }
  ```
  Воркер: `onmessage` с `{ id, job }` → `renderVariants(job.preset, job.seeds)` → `postMessage({ id, out }, out.map((s) => s.buffer))`; ошибка рендера → `{ id, error }` → промис отклоняется.
