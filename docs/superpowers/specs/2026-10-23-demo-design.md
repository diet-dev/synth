# Демка @dietdev/synth: генератор звуков на GitHub Pages

## Зачем

Автор пакета подбирает звуки для своих игр. Сейчас пресет пишется руками в
коде и слушается только в игре. Нужна страница, где можно послушать готовые
примеры, нажать кнопку категории («монетка», «клик»…), получить случайный звук
этого типа, подкрутить его ползунками и скопировать готовый пресет в код игры —
аргумент `render()` / `renderVariants()`.

Пользователь — сам автор (и любой, кто придёт по ссылке из README/npm). Это
рабочий инструмент, а не рекламная витрина.

Сценарий: **кнопка категории → слушаю → кручу ползунки / «мутировать» →
«Копировать» → вставляю в игру.**

## Цели

1. Страница публикуется на GitHub Pages автоматически при пуше в `master`:
   `https://diet-dev.github.io/synth/`.
2. Один экран (раскладка «A», утверждена по наброску), три колонки:
   - **слева** — кнопки категорий генератора, «🎲 Мутировать», список готовых
     примеров;
   - **в центре** — волна текущего звука, «▶ Играть» (и пробел), редактор
     всех параметров пресета;
   - **справа** — код пресета, обновляется вживую; «📋 Копировать»,
     «⬇ WAV».
3. Редактор показывает **всё**, что умеет `Preset` (решение автора):
   - общие поля: `ms`, `fade`, `lp`, `lpPasses`, `peak`;
   - список голосов: добавить (тональный / классический), удалить,
     дублировать, переключиться;
   - тональный голос (`Voice`): `wave`, `hz`, `toHz`, `duty`, `noise`, `gain`,
     `env` (`a`, `h`, `d`, `exp`), `pulses` (`rate`, `jitter`, `ampJitter`,
     `decay`, `len`), `am`, `fm` (`hz`, `depth`), `lp`, `hp`;
   - классический голос (`Classic`): все поля типа, включая `jump`, `repeat`,
     `vib`, `duty`/`dutySlide`, `env` с `punch`, `lp`/`hp`/`phaser` со сдвигами,
     `minHz`/`stopAtMin`, `gain`.
   Необязательные блоки (`pulses`, `am`, `fm`, `jump`, фильтры…) включаются и
   выключаются галочкой: выключенный блок в пресет не попадает.
4. Любое изменение сразу перерисовывает волну и проигрывает звук заново.
5. **Режим цикла** (решение автора) — для звуков, которые игра перезапускает
   по кругу (мотор, гул, трещотка; см. README «Зацикленный звук
   перезапуском»). Кнопка «🔁 Цикл / ■ Стоп» запускает клип с периодом `P`,
   как в игре, чередуя 2–3 варианта (сида). `P` — ползунок рядом с кнопкой
   (по умолчанию 216 мс = 13 кадров при 60 FPS). Пока цикл играет, правки
   пресета подхватываются со следующего перезапуска, без остановки.
   Категории мотор/гул/трещотка открываются сразу в режиме цикла.
6. Категории генератора:
   - **игровые, по мотивам генераторов sfxr** (классический голос): монетка,
     лазер, взрыв, бонус, удар, прыжок, блип;
   - **свои** (тональный голос, толчки): мотор, гул, трещотка;
   - **интерфейс** (по просьбе автора): клик, наведение, переключение
     вкладки/пункта меню, открыть, закрыть, подтверждение, ошибка.
7. Готовые примеры: шесть рецептов из раздела README «Рецепты» (CLICK, COIN,
   BOOM, SHOT, ENGINE, LASER) плюс по одному удачному звуку на каждую
   интерфейсную категорию. Клик по примеру — загрузить в редактор и сыграть.

## Не цели

- Мобильная вёрстка (автору «на телефоны пофиг»). Целевой экран — десктоп от
  ~1280 px; на узком экране страница может просто прокручиваться.
- Паузы, плейлисты, плеер для музыки (цикл перезапуском из цели 5 — не плеер).
- Аккаунты, сохранение библиотеки звуков на сервере.
- Английская версия интерфейса.
- Изменения публичного API пакета ради демки.

## Анти-цели (провал, даже если «работает»)

- **Тормоза.** Ползунок не должен дёргаться и залипать; звук должен
  отзываться без заметной задержки.
- **Противные звуки.** Случайный звук из любой категории не должен резать
  уши: без клиппинга, без писка на краю слышимости, без оглушающей громкости,
  без бесконечно долгих хвостов. Интерфейсные звуки — короткие и тихие.
- **Некрасиво.** Страница должна выглядеть как аккуратный инструмент, а не как
  форма из 90-х: ровная сетка, понятная группировка параметров, читаемый код
  пресета, тёмная и светлая тема по системной.

## Как сделано (решения)

Решения автора:
- раскладка «A»; редактор — все параметры; группа «Интерфейс»; режим цикла
  для мотора, гула и трещотки; публикация на
  GitHub Pages.

Мои решения (автор их не обсуждал — можно оспорить):
- **Сборка — Vite, чистый TypeScript без фреймворков.** Папка `demo/`
  (`index.html`, `main.ts`, модули, `style.css`). `vite.config.ts` в корне:
  `root: "demo"`, `base: "./"`; демка импортирует `../src/index.ts`
  (всегда текущий код; тесты демки в Node тоже идут по исходникам), сборка в `dist-demo/`. `vite` —
  devDependency; скрипты `dev`, `build:demo`, `preview`.
- **Публикация** — `.github/workflows/demo-pages.yml`: на пуш в `master` и
  вручную (`workflow_dispatch`); `npm ci` → `npm run build:demo` →
  `actions/upload-pages-artifact` (`dist-demo`) → `actions/deploy-pages`;
  права `pages: write`, `id-token: write`; `concurrency: pages`. Один раз
  вручную на GitHub: Settings → Pages → Source: **GitHub Actions**.
- `dist-demo/` — в `.gitignore`. Демка не попадает в npm-пакет (`files` уже
  ограничен `dist`, `src`, `NOTICE.md`).
- **Звук — Web Audio** (`AudioBuffer` из `Float32Array`), а не `<audio>` с
  data URL: мгновенный старт, предыдущий звук обрывается новым. `toWav` —
  только для «⬇ WAV».
- **Рендер вне главного потока, если нужно.** Тональные звуки рендерятся за
  миллисекунды, классические длинные шумы — десятки мс. Изменения ползунков
  схлопываются до одного рендера на кадр; если рендер дольше ~16 мс — он
  уходит в Web Worker, а устаревшие результаты отбрасываются. Порог и
  механизм — на усмотрение исполнителя, критерий — анти-цель «тормоза».
- **Одиночное проигрывание — `renderVariants(preset, [seed])`**, один сид:
  `peak` нормализует ровно этот вариант. Сид показывается и меняется кнопкой
  «другой вариант».
- **Цикл — `renderVariants(preset, [s1, s2, s3])` одним вызовом**, с общей
  нормализацией, как в игре: тихие варианты остаются тише. Клипы ставятся на
  временную шкалу `AudioContext` с небольшим упреждением (~0,2 с), раз в `P`,
  случайный вариант; занятый экземпляр не перезапускается — так же, как
  `SfxPlayer` с пулом. Перерендер трёх вариантов при правке идёт тем же путём
  (кадр / Worker), старые клипы доигрывают.
- **Ползунки во время перетаскивания** перерисовывают волну каждый кадр, а
  звук проигрывают по отпусканию (и по каждому шагу с клавиатуры) — иначе
  длинный звук заикается 60 раз в секунду. В режиме цикла правки и так
  слышны со следующего перезапуска.
- **Копирование у звуков для цикла** добавляет к литералу пресета строку с
  рендером вариантов и комментарий с периодом, как в рецепте мотора README:
  `const urls = renderVariants(ENGINE, [1, 2, 3]).map((s) => toWav(s)); //
  перезапуск раз в 216 мс`.
- **Генераторы пишутся сразу в естественных единицах** (Гц, мс, окт/с),
  повторяя логику и диапазоны генераторов sfxr (pickup/coin, laser, explosion,
  powerup, hit, jump, blip). Переводчика из шкал jsfxr в репозитории больше
  нет и возвращать его не нужно. Авторство sfxr уже указано в `NOTICE.md`.
- **Генераторы — чистые функции `(rand) => Preset`** в отдельном модуле демки
  (`demo/generators.ts`), ГПСЧ — `rng(seed)` пакета, чтобы звук
  воспроизводился. «Мутировать» — небольшой случайный сдвиг числовых
  параметров текущего пресета в допустимых пределах.
- **Пределы против «противных звуков»** заданы в генераторах: длительность
  (игровые ≤ ~1,5 с; мотор/гул/трещотка — клип ~250 мс с `fade` под перезапуск
  раз в `P`, длина клипа ≥ `P` + `fade.out`; интерфейс ≤ ~150 мс),
  частоты в слышимой и не режущей области, у всех генераторов задан `peak`
  (интерфейс — тише игровых).
- **Код пресета** — компактный TypeScript-литерал (как в рецептах README), без
  полей со значениями по умолчанию и без выключенных блоков; числа
  округлены до разумной точности **у тональных голосов**, у классических —
  не округляются (README предупреждает: округление сдвигает целочисленный
  период тона sfxr).
- **Текущий пресет хранится в URL (`#…`)** — переживает перезагрузку, ссылкой
  можно поделиться. В `localStorage` ничего важного не держим.
- Интерфейс на русском, как README. Тёмная/светлая тема — по системной.
- В README — ссылка на демку в начале и в «Разработке» (`npm run dev`).

## Проверка

- `npm test` и `npm run typecheck` покрывают и демку (tsconfig включает
  `demo/`).
- Тесты генераторов (node:test, без браузера): для каждой категории и
  сотни сидов пресет валиден, рендер без NaN, длина и пик в пределах
  категории, повторный вызов с тем же сидом даёт тот же пресет.
- Тест сериализации: код пресета из правой колонки, исполненный как JS,
  даёт пресет, рендер которого совпадает с исходным.
- Примеры демки, взятые из README, совпадают с рецептами README (чтобы не
  разъехались).
- Ручная проверка в браузере (`npm run dev`): каждая кнопка, ползунки без
  рывков, цикл без щелчков и провалов на стыках, копирование, WAV, обе темы.
- `npm run build:demo` собирается; workflow проверяется первым пушем.

## Оставлено исполнителю

Визуальный стиль в пределах анти-цели «некрасиво»; вид ползунков и
группировка параметров; отрисовка волны; точные диапазоны ползунков;
формулы генераторов в пределах описанного; иконки категорий; горячие
клавиши помимо пробела.
